ホームページを開いたら、ブラウザに「この接続ではプライバシーが保護されません」と出てしまった。そんな画面、見たことありませんか？

原因としてよくあるのが、SSL証明書（サイトが本物で、通信が暗号化されていることを示す身分証みたいなもの）の期限切れです。無料で使える Let's Encrypt は自動更新ができるので安心しがちなんですが、実は「自動更新を設定したつもりで、動いていなかった」ということが起きやすいんですよね。

今日は、Let's Encrypt の自動更新がちゃんと動いているかを確かめる方法をまとめます。

## なぜ「自動更新の確認」が大事なのか

Let's Encrypt の証明書は、有効期限が90日と短めです。手で更新し続けるのは現実的ではないので、certbot（証明書の取得・更新をしてくれるツール）で自動更新するのが前提になっています。

ただ、自動更新は「失敗しても誰も気づかない」のが怖いところです。以前は期限が近づくと Let's Encrypt から注意のメールが届いていたんですが、このお知らせメールは2025年に終了しています。つまり、自分で確かめる仕組みを持っておかないと、期限切れに気づくのはお客さんから連絡が来たとき、なんてことになりかねません。

さらに、Let's Encrypt は今後、証明書の有効期限をもっと短くしていく方針も発表しています。更新の回数が増えるほど、自動化がちゃんと動いていることの大切さは増していくなと思います。

## 確認1：自動更新のタイマーが動いているか

certbot を apt や snap で入れた場合、多くの環境では systemd のタイマー（決まった時間にコマンドを動かす仕組み）が自動で用意されます。まずは、これが有効になっているかを見ます。

```shell
systemctl list-timers | grep certbot
```

`certbot.timer` や `snap.certbot.renew.timer` が表示され、次に動く時刻（NEXT）が入っていればOKです。何も出てこない場合は、cron（Linuxで定期実行を設定する仕組み）に書かれていないかも確認してみてください。

```shell
sudo grep -r certbot /etc/cron* 2>/dev/null
```

タイマーもcronも見つからなければ、自動更新は動いていません。

## 確認2：dry-runで更新のリハーサルをする

タイマーが動いていても、更新そのものが失敗していては意味がありません。そこで使うのが dry-run（本番の更新はせずに、手順だけ試すリハーサル）です。

```shell
sudo certbot renew --dry-run
```

最後に「Congratulations, all simulated renewals succeeded」のように表示されれば、更新の流れは問題なく通っています。

失敗するときによくある原因は、次のようなものです。

- 80番ポート（HTTPの通信の入口）がファイアウォールで閉じている
- DNS（ドメインとサーバーをつなぐ住所録みたいなもの）の向き先が変わっている
- nginxの設定を書き換えて、認証用のURLに届かなくなっている

サーバーの引っ越しやnginxの設定変更をしたあとは、dry-runを一度走らせておくと安心です。

## 確認3：更新後にnginxが新しい証明書を読み込むか

見落としがちなのがここです。証明書のファイルが新しくなっても、nginxが古い証明書を読み込んだままだと、ブラウザには古い期限のまま見えてしまいます。

certbot の nginx プラグイン（`--nginx`）を使って取得した場合は、更新後の再読み込みもやってくれます。一方、`--webroot` などで取得して、nginxの設定を自分で書いている場合は、更新後に再読み込みするように指定しておきます。

```shell
sudo certbot renew --deploy-hook "systemctl reload nginx"
```

deploy-hook は、実際に証明書が更新されたときだけ動く命令です。一度この形で更新すると設定ファイルに記録され、次からの自動更新でも使われます。

サッカーでいうと、新しいユニフォームが届いたのに、ロッカーにしまったまま古いユニフォームで試合に出ている状態です。届くだけでなく、ちゃんと着替えるところまでがセットなんですよね。

## 確認4：今の期限を自分の目で見る

最後に、実際に公開されている証明書の期限を確認します。サーバーの中からなら、これで一覧が見られます。

```shell
sudo certbot certificates
```

外から見た証明書の期限は、openssl（暗号化の通信を扱うツール）で確かめられます。

```shell
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | openssl x509 -noout -enddate
```

`notAfter=` のあとに表示される日付が期限です。certbot は、期限まで残りが少なくなった証明書を更新する仕組みなので、期限が先に延びていれば自動更新は効いています。

ブラウザでも、アドレスバーの鍵のマークから証明書の情報を開けば期限を見られます。

## 僕が意識していること

自動更新は「設定したら終わり」ではなく、「動いていることを確かめるまでが設定」だと思っています。特に、サーバーを作り直したときや、nginxの設定を変えたときは、dry-runと期限の確認をセットでやるようにしたいところです。

外部の監視サービスで、証明書の期限が近づいたら通知してもらう方法もあります。お知らせメールがなくなった今は、こうした仕組みを1つ用意しておくと安心ですね。

## 今日のポイント

Let's Encrypt の自動更新は、タイマー・dry-run・nginxの再読み込み・期限の確認の4つで「本当に動いているか」を確かめるのが大事です。

ホームページのSSLやサーバーまわりで困っていることがあれば、気軽に相談してくださいね。
